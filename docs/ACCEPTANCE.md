## 2026-10-29 发布前复验

推送 `9c76826` 后，[远端 CI](https://github.com/jiazixin/video-rename/actions/runs/40720416719) 的 Web、Chromium E2E 和多目标快照构建通过，Go 竞态任务中的 `TestNumberingBackgroundPreviewConfirmationAndPaging` 在等待实际编号提交时触发测试辅助函数固定的十秒期限。本机定向重跑在 macOS 和 Linux/arm64 均连续三次通过，因此不能把该次 CI 超时解释为已稳定复现的生产死锁。

该辅助函数原先直接读取内部状态，不经过负责续租的状态接口；这也无法正确模拟超过二十秒的正常客户端等待。现在通过状态接口轮询并续租，用 `t.Context()` 派生一分钟的卡死保护期限，并在超时时输出最后状态与进度。没有修改生产超时、落盘顺序、文件安全检查，也没有降低 205 个文件、完成状态及三页预览结果的断言；状态响应额外检查 HTTP 200 和 JSON 解码成功。

本次补修的实际验证如下，日志在 `.cache/release-v1.1.4/`：

- macOS：编号相关测试执行三轮竞态检查通过（`numbering-mac-after.log`），app 包完整竞态检查通过（`app-mac-after.log`）。
- Linux/arm64 隔离容器：Go 1.27.3、FFmpeg/ffprobe 7.1.5、限制两颗 CPU，完整 `go test -race -count=1 ./...` 的 **27 个测试包**通过（`linux-full-after.log`）。容器只挂载源码副本、构建资源及依赖缓存，媒体与数据库仍由隔离夹具创建。
- 受影响文件的 gofmt / goimports、app 包的 vet / staticcheck 与 `git diff --check` 通过。
- 最初的通用 Go 容器缺少 ffprobe，导致依赖该工具的历史重试用例失败；补齐实际测试镜像的工具条件后完整重跑通过，没有改动这些用例的断言。

本次只修改测试等待与验收记录，运行时代码和前端未改动。新提交的远端运行结果以 [main 的 CI](https://github.com/jiazixin/video-rename/actions/workflows/ci.yml?query=branch%3Amain) 为准，不以本机通过代替发布前的远端检查。

## 验证边界

- 所有验证均为本机隔离数据，没有转换、删除或试开用户数据库。
- 交叉 vet / 编译不等于目标环境实机运行；本次另有上述 Linux/arm64 容器回归，仍不能代替真实 NAS 或其他架构验证。浏览器自动化为 Chromium，Firefox / Safari 最低版本未实测。
- 编号检查取消的边界是文件系统调用之间；已进入内核且阻塞的 NAS 调用必须先返回，不能承诺硬中断。冻结预览与恢复仍需持有文件操作锁。
- 本机磁盘、合成索引和短时 Fuzz 不能代表 NAS 延迟、真实模型吞吐或全部输入空间。精确总数、深 OFFSET 与全历史分位数仍有随数据规模增长的成本。
- 本轮未重跑 50 万 / 53 万真实临时文件的独立大规模实验；已完整运行上述 12 项标准规模用例。依赖维护限制仍见开发说明，本次不升级依赖。
