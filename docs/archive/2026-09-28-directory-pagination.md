# 目录刷新与分页体验

用户授权由实现方决定交互并完成改进。

## 决定

目录页使用按页码读取的接口，每次请求在同一个数据库读快照中取得目录版本、总数和本页 ID。后台重扫不再使目录页的分页请求报版本过期；原有游标接口继续供逐页遍历使用，保留版本检查。

后台更新按 ID 更新当前行，保留勾选、顺序与滚动位置。主动翻页、筛选、排序及刷新使用最新排序；刷新保留页码，筛选、排序和每页数量改变回第一页。目录缩小时收敛到最后一个有效页，空目录为第一页。返回已访问目录继续恢复保存的页码和位置。

采用页码读取，避免在每次后台扫描后要求用户重试，也避免取消游标版本校验后继续沿用旧的分页边界。代价是深页读取使用 SQL OFFSET；不在本次改动中引入长时间保留的服务端浏览会话或全量文件缓存。

## 实施与验证

1. library 新增页码读取模式，与游标模式复用过滤和排序，在读事务中查询，页码先收敛再计算偏移，覆盖刷新、排序、筛选、删除及超大页码。
2. HTTP entries 路由接受 page；目录页面保存页码，后台更新保留行的位置；不覆盖工作区既有 Toast 和状态文案改动。
3. 浏览器回归覆盖第二页后台刷新、跨页勾选、删除导致页数减少、目录返回定位以及迟到响应。
4. 执行前端检查和构建、Go 测试与静态检查、相关浏览器测试；同步 README 与开发说明。

## 验证结果（2026-09-28）

本次工作区验证保留已有 Toast、历史页、批次页和主题改动。测试使用临时媒体和数据库。

- `npm --prefix web run check`、`npm --prefix web run build`、`go build -o bin/video-rename ./cmd/video-rename` 通过。
- `go test ./...`、`go vet ./...` 通过。默认 Go 缓存受沙箱限制，后续 Go 命令使用 `GOCACHE=/private/tmp/video-rename-go-cache`；涉及本地端口的测试在获准的沙箱外执行。
- `go test -race ./internal/library ./internal/app` 中 app 通过；library 首轮的静态排序对照测试因运行超过 30 秒触发自动扫描而失败。已在各排序对照开始前刷新索引，使静态对照独立于整体运行时间；`go test -race ./internal/library -run '^TestListPage' -count=1` 复验通过，包含专门的并发重扫测试。
- `npm --prefix web run test:e2e -- library-pagination.spec.ts`：4 项通过，覆盖重扫后跨页勾选、第二页后台改名原位更新、目录缩小与空目录、迟到响应与真实错误重试。
- `npm --prefix web run test:e2e -- workspace.spec.ts --grep '惰性子目录|迟到的目录刷新|自动命名原位|返回目录恢复|切换页面后返回上级|首次进入目录|目录标记'`：7 项通过，覆盖原有分页、多选、自动命名与返回定位。
- `go test -tags=scale ./internal/library -run '^TestScaleDirectoryPagination$' -count=1 -v` 通过。本机 50,000 文件目录的页码模式第 1 / 250 / 500 页分别约 62 / 99 / 137 ms；原有游标模式 30 页的 P95 约 26 ms。只代表隔离本地数据，未验证真实媒体挂载的端到端耗时。
