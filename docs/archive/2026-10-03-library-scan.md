# NAS 媒体目录后台扫描实施计划

**目标：** 持续发现媒体根目录内新增、修改与移除的文件。自动扫描默认开启、间隔为 60 分钟；用户可选择目录范围、手动递归扫描或停止本轮。

**架构：** 独立扫描协调器管理应用生命周期中的单轮任务，定时与手动入口共享状态，不创建命名或抽帧批次。磁盘元数据读取不占用库级文件操作锁，发布前核验目录身份与索引基线；扫描失败继续保留上次完整列表。设置使用已有 system_settings.policy 的独立 JSON 字段保存，避免改变既定数据库结构。

**技术栈：** Go 1.27.1、SQLite、Vue 3 / TypeScript；使用现有目录索引、目录选择器和原生构建验证命令。

## 已确定的行为

- 默认范围为整个媒体根，允许选择多个目录，包含新增子目录，不跟随符号链接。
- 上一轮结束后等待设定间隔，默认 60 分钟；启动时等待一个间隔，不立即全库扫描。修改设置后重新计算下一轮时间。
- 自动与手动扫描最多一轮，重复触发返回正在运行的一轮；手动扫描不需要启用自动扫描。
- 目录逐个遍历，读属性与暂存分批进行；未变化目录避免重建索引。成功完整扫描后才发布目录结果。
- 目录读取失败保留旧列表、记录错误并继续独立目录；媒体根或挂载身份异常时停止本轮。
- 停止只取消后续工作，等待在途不可中断的文件系统调用退出；已发布目录保留。
- 页面可见时轻量读取索引版本，有变化时同步当前页；选择、编辑和播放期间提示更新而不打乱操作。

## 实施步骤与归属

1. `internal/library`：新增安全后台目录扫描原语，协调现有单目录刷新；验证慢属性读取、并发改名、替换目录、取消、失败与未变目录。
2. `internal/systemsettings`：新增扫描设置的独立读写，默认 enabled=true / interval_minutes=60 / targets=[1]，保存不覆盖其他处理设置；验证重启保留和并发保存。
3. `internal/libraryscan`：新增协调器与生命周期、定时调度、范围规范化、状态和错误明细；验证默认间隔、单轮去重、新子目录、取消和异常继续。
4. `internal/app`：接入读取/保存扫描设置、开始/停止和目录轻量状态接口，沿用登录与 CSRF 校验；关闭服务等待扫描退出。
5. `web/src/features/settings` 与 `web/src/features/library`：加入配置、手动按钮、状态与更新提示，保留现有单层刷新和目录会话。
6. 更新当前 README / 配置与运行文档，补相应 Go 和浏览器行为验证。

## API

- `GET /api/library/scan`：读取扫描设置和当前/最近一轮状态。
- `PUT /api/library/scan/settings`：保存 enabled、interval_minutes（5–1440）、targets（1–100 个媒体根内目录）。
- `POST /api/library/scan`：可传 targets，省略或空数组使用已保存范围，返回当前轮状态。
- `POST /api/library/scan/cancel`：停止当前轮。
- `GET /api/directories/{id}/state`：轻量读取完整索引 generation / refreshed / error / refreshing，不触发扫描。

## 验证

先 `npm --prefix web run build` 生成嵌入资源，再运行受影响 Go 测试；完成后运行 format:check、check、build、go test -count=1 ./...、go test -race -count=1 ./...、go vet ./...、go mod verify 和本地构建。浏览器使用现有 18790 隔离夹具验证扫描设置、手动发现新文件和列表更新。真实 NAS 吞吐与断网系统调用延迟需要相应环境实测，不将合成延迟测试称为 NAS 性能验证。
