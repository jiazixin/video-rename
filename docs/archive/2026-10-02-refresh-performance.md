# 大规模目录刷新性能优化

目标：继续降低递归标记的目录刷新开销，兼顾性能和稳定。生产测量为529654文件共394.262秒，其中刷新264.188秒、校验102.311秒、标记写入25.575秒；优先处理刷新，标记提交上限维持128。

方案：刷新每页仍128项，最多4个worker读取文件属性；整页完成后再打开短数据库事务，失败或取消时等待在途属性读取退出，不发布不完整generation。复用页内SQL语句，保持observed更新、identity替换、version推进及完整目录快照规则。仅复用同次锁内读取的目录基础字段，不跨文件缓存路径证据。保留WAL + FULL、单写连接、Library.mu及逐文件标记校验。

记录目录枚举、属性读取和索引事务/发布的耗时，并补充到标记完成日志，以区分SMB与数据库开销。Go可能在ReadDir中读取属性，因此枚举与属性两项都属于文件系统阶段。

验证：先记录当前2万文件及512文件注入2ms属性延迟的基线；新增并发上限、输入顺序、失败页无写入、取消等待退出、数据库可用与identity/version/generation回归。执行受影响测试、全Go测试、library/app/jobs race、静态检查、两平台构建及标记浏览器专项。重跑相同规模和50万真实临时文件，校验精确计数、SQLite完整性和外键，明确本机与真实SMB测量的区别。

本轮不改数据库结构、同步级别、用户配置或实际媒体/数据库。完成后归档计划，更新开发与验收说明，不自动提交或部署。

已实施internal/library/refresh.go及标记日志聚合，补齐属性/索引/最终发布失败、取消等待、并发与顺序回归。独立审查发现并修正“后续项先失败时跳过已分配早项”的错误顺序问题，采用最早失败索引停止后续读取，并保留早项完成与取消收尾。
