# 历史计划：1.0 发布安全修复

> 实施步骤已完成；测试结果与发布判断只维护在 [最新验收](../ACCEPTANCE.md)。

**目标：** 关闭审查确认的两项 P1 和一项 P2，经隔离故障回归、完整测试及发布构建后给出明确发版判断。

**设计：** 延续已有持久日志和恢复机制，不迁移数据库、不升级依赖。缓存路径规则在配置层统一定义并由缓存使用；改名在日志写入后与移动后复核快照；任务终态事务化并向调度层传播持久化失败。

**技术：** Go 1.27.1、SQLite、已有 Vue/Playwright 套件。当前工作区保留上轮审查文档变更，直接在此修复。

1. 配置：在 `internal/config/service.go` 定义缓存受管路径，拒绝媒体、storage、数据库及配置落入受管根；`internal/framecache/cache.go` 复用路径。测试父子重叠、符号链接、正常布局与拒绝时数据不变。
2. 文件提交：`internal/library/operations.go` 写 prepared 后复核源，移动后复核目标；异常保留 prepared 并停止提交，由现有 Recover 判断 review/interrupted。在同包测试中注入源替换、同 inode 内容变化、同名自动提交及提交后异常，验证无假成功、不覆盖与恢复。
3. 批次：`internal/jobs/processing.go` 终态与计数事务化，`concurrency.go` 收集工作线程错误并停止派发；`execute.go` 处理失败与最终事务，保留文件日志事实。故障注入验证终态写、计数写、批次收尾、取消和恢复，不产生假成功。
4. 先确认新增测试在基线上失败，再实现并跑相关包；随后全仓测试、竞态、vet、FFmpeg 集成、182 项浏览器套件、scale/scale_large、干净源码构建/启动和 Linux 交叉编译。
5. 再审查最终差异；同步双语说明及开发文档。旧验收与本计划归档，最新结果只记录在 `docs/ACCEPTANCE.md`。不提交、打标签或发布。
