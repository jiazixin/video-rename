# 大目录标记断连修复

## 问题与证据

用户报告两个目录约 20,000 个文件偶尔未标记完整，访问经过反向代理、使用 HTTP/2，当时没有命名任务。原接口在请求内扫描并逐文件提交，使用请求 context；代理或浏览器断连会取消剩余工作。部分分页或目标之间的取消分支没有明确报告中断。

本机两个目录共 20,000 个视频的原流程首次标记、重复标记、取消标记均完整，耗时分别约 16.4、15.8、17.3 秒。未取得用户代理日志，不能确认两次故障的具体超时设置或状态码。

## 方案

采用后台执行加短请求查询。仅调大代理超时仍受存储耗时与客户端连接影响；响应流需要适配代理缓冲和前端解析。后台任务复用现有逐文件校验与提交，保留当前数据库结构。

- 页面提交请求键，立即取得运行状态；每秒查询一次已提交数量。
- 服务端任务使用应用 context，断连不取消；相同键重试返回原任务。
- 标记任务串行执行，避免不同页面相反操作交错；文件失败继续报告。
- 服务关闭取消并等待工作退出，任何取消均明确报告 interrupted。
- 终态进度在内存保留一小时、最多 128 项。服务重启后重新操作，已经落库的标记不丢失；不承诺自动恢复未完成部分。

## 验证

- library：跨文件与跨目标取消后报告中断，重试只补剩余标记。
- app：请求取消后跨两个目录、多次分页完成；相同键返回原计数；参数冲突、并发标记、文件失败、关闭、未知任务和登录保护。
- scale：两个目录各 10,000 个视频，取消提交请求后核对数据库全部 20,000 条标记。
- 浏览器：进度展示、查询断连后的同键重试、实际目录标记与跨页取消。
- 类型检查、生产构建、Go 测试、受影响包竞态检查与静态检查。
