# Web 服务配置

完整可复制示例在 [configs/config.example.yaml](../configs/config.example.yaml)。所有 YAML 配置路径相对于配置文件所在目录；默认读取 `configs/config.local.yaml`，也可通过 `--config/-f` 显式指定。不读取环境变量覆盖，未知字段、重复 key 和非法配置类型报错。

| 字段 | 默认 / 要求 | 作用 |
| --- | --- | --- |
| listen | 127.0.0.1，IP 地址 | HTTP 监听地址，局域网可配置 0.0.0.0 |
| port | 8790，1–65535 | HTTP 端口 |
| path | 必填，已存在的真实目录 | 媒体根目录，不能通过 HTTP 越界访问 |
| storage | ../data | 数据目录，自动创建，必须在媒体根目录外；内部数据库文件名固定 |
| tmp-storage | ../.cache | 可重建截图缓存的父目录，必须在媒体根目录外，修改后重启 |
| auth.username | 必填 | 管理员账号 |
| auth.password | 非空，拒绝占位密码，无最短长度限制 | 管理员密码，仅后端读取，不写入数据库或 API 响应 |

`logging` 已退出 Web 服务协议。成功 / 失败记录、操作历史和处理标记统一使用 SQLite。已有内部流水线测试仍使用旧日志结构，它不是 Web 服务的配置入口。

模型协议、图片预算、有限重试、标题清洗和 FFmpeg 调用规则沿用 [媒体处理](processing.md)。工具路径从 PATH 查找，不通过 YAML 拼接命令。

监听、根目录、认证和数据库配置变更需要重启。模型 URL、密钥、模型名、温度、输出上限和超时全部在“模型配置”页面保存；YAML 不支持 server，不兼容、不导入旧字段。计划规则和目标目录在页面管理并持久化到 SQLite，不同步写回 YAML。

并发任务数在系统设置的模型配置页签保存（1–32，默认 2），YAML 不再支持 workers。保存后并发数同步应用于该模型配置的排队和运行中批次，其他请求参数保留原快照。


`storage` 省略时使用 `../data`（相对于配置文件目录）；项目默认配置位于 `configs/`，因此数据落在项目根目录的 `data/`。填写自定义位置时只提供目录，例如 `storage: "/srv/video-rename/data"`。程序在该目录中管理 `data.sqlite`、密钥、锁和 SQLite 辅助文件，备份时保留整个目录。


## Web 抽帧设置

「系统设置 → 抽帧设置」统一管理抽帧策略、最大帧数、首尾跳过比例、时长/大小档位、图片最长边和 JPEG 质量。设置保存到 SQLite，不写回 YAML；YAML 不支持 sampling 和 images，无导入或兼容处理。

默认 hybrid，最多 12 帧，首尾各跳过 5%，图片最长边 768 像素，JPEG 质量 4。最大帧数和每档帧数为 1–32；首尾跳过比例之和小于 100%；最长边 128–2048 像素；JPEG 质量 2–15（越小通常越清晰）。

时长档位默认为 30s/3 帧、2m/5 帧、10m/8 帧、30m/10 帧，其余 12 帧；大小档位为 50MiB/3 帧、200MiB/5 帧、1024MiB/8 帧，其余 12 帧。上限严格递增，末档固定覆盖其余范围。时长输入支持 30s、2m、1h。混合策略按时长为主，大小辅助最多增加 2 帧；实际帧数同时受最大帧数和有效采样窗口长度限制。

手动运行、自动计划和失败重试创建批次时，读取当前设置并保存快照。保存新设置立即作用于以后创建的批次，已有批次使用创建时的抽帧和图片参数。

## 系统资源设置

「系统设置 → 处理与缓存」保存抽帧并发数（默认 8，1–32）与临时缓存容量（默认 10 GB，1–10000，1 GB = 10^9 字节）。两者保存到 SQLite，不写回 YAML。模型并发仅控制请求，按模型配置跨批次共享；抽帧并发全局共享。

`tmp-storage: "../.cache"` 与 storage 一样按配置文件目录解析，显式空值无效，路径不得通过符号链接落入媒体根。程序使用其下专属 `video-rename-frames-v1/`，连续 72 小时未使用的完整缓存自动清理；成功改名立即删除，失败/取消保留。容量不足先淘汰闲置旧缓存，保护使用中的截图；降低容量时正在使用的空间可能暂时超出新上限，任务释放后自动收敛。

「处理与缓存」还提供“文件稳定性检查”：等待时长默认 30 秒，范围 0–3600 整数秒，0 禁用等待。设置保存到 SQLite，刷新与重启保留；后续开始的批次读取新值，已有批次保持开始时读取的时长。禁用等待不关闭处理前、模型请求前和改名前的文件变化核对。
