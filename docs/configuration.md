# Web 服务配置

完整可复制示例在 [configs/config.example.yaml](../configs/config.example.yaml)。所有 YAML 配置路径相对于配置文件所在目录；选择顺序为 `--config/-c` > 环境变量 `CONFIG_FILE` > 工作目录下的 `configs/config.local.yaml`，文件必须存在。除 `CONFIG_FILE` 外不读取环境变量覆盖，未知字段、重复 key、多个 YAML 文档和非法配置类型报错。

| 字段 | 默认 / 要求 | 作用 |
| --- | --- | --- |
| listen | 127.0.0.1，IP 地址 | HTTP 监听地址，局域网可配置 0.0.0.0 |
| port | 8790，1–65535 | HTTP 端口 |
| media-path | 必填，已存在的真实目录 | 媒体根目录，不能通过 HTTP 越界访问 |
| storage | ../data | 数据目录，自动创建，必须在媒体根目录外；内部数据库文件名固定 |
| tmp-storage | ../.cache | 可重建截图缓存的父目录，必须在媒体根目录外，修改后重启 |
| auth.username | 必填 | 管理员账号 |
| auth.password | 非空，拒绝占位密码，无最短长度限制 | 管理员密码，仅后端读取，不写入数据库或 API 响应 |

配置包含明文管理员密码，建议文件权限设为 `0600`，使用独立运行账号；不要把配置文件纳入公开版本库。认证配置变更需要重启，并使旧会话失效。

模型协议、图片预算、有限重试、标题清洗和 FFmpeg 调用规则见 [媒体处理](processing.md)。工具路径从 PATH 查找，不通过 YAML 拼接命令。

监听、根目录、认证和数据库配置变更需要重启。模型 URL、密钥、模型名、温度、输出上限和超时全部在“模型配置”页面保存。后台扫描设置、计划规则和目标目录在页面管理并持久化到 SQLite，不同步写回 YAML。

## 后台目录扫描

“系统设置 → 后台目录扫描”提供后台扫描开关、扫描间隔、扫描范围和排除目录，页签位于“处理与缓存”之后。默认开启，间隔 **60 分钟（1 小时）**，范围为整个媒体根；允许选择 1–100 个已有目录，包含新建子目录。间隔为 5–1440 整数分钟，设置保存后无需重启。

扫描范围和排除目录统一使用列表与加号打开的多选弹窗，支持跨目录选择、取消和逐项移除；确认只更新草稿，点击“保存扫描设置”后持久化。排除目录最多 100 个，可以清空，父子重叠自动合并。排除优先于扫描范围，手动扫描（包括显式选择被排除目录的子目录）与后台扫描均跳过相应子树。运行中的扫描冻结启动时的排除列表，新设置从下一轮生效。规则跟随所选目录的索引 ID；不删除已有索引，也不限制按需浏览索引、命名或抽帧，不作为访问控制。

服务启动时先等待设定间隔，不立即全库扫描；每轮结束后再等待该间隔。手动扫描无需开启自动扫描，文件目录页可扫描当前目录及子目录，设置页可立即扫描已保存范围。一次只运行一轮，重复触发复用当前进度，不堆积任务。扫描只更新索引，不启动抽帧、命名或编号。

关闭自动扫描只停止后续触发；停止当前轮使用“停止扫描”。已发布的目录结果保留。重启保留设置，最近一轮的内存进度不续跑。NAS 目录数量较大时可延长间隔，实际扫描耗时和失败明细显示在页面。

并发任务数在系统设置的模型配置页签保存（1–32，默认 2），保存后并发数同步应用于该模型配置的排队和运行中批次，其他请求参数保留原快照。

`storage` 省略时使用 `../data`（相对于配置文件目录）；项目默认配置位于 `configs/`，因此数据落在项目根目录的 `data/`。填写自定义位置时只提供目录，例如 `storage: "/srv/video-rename/data"`。程序在该目录中管理 `data.sqlite`、密钥、锁和 SQLite 辅助文件，备份时保留整个目录。

## Prompt配置与标题失败关键词

“系统设置 → Prompt配置”维护固定提示词、提示词库和标题失败关键词。失败关键词默认是“命名失败”“拒绝”“无法完成”“sorry”；模型返回的标题包含任一词或句子即判命名失败，匹配忽略大小写，保留原文件名并按现有重试规则处理。

可逐项添加或删除，最多 100 条，每条 1–200 个 Unicode 字符，首尾空白会移除，忽略大小写的重复项只保留一条。关键词过于宽泛时可能误判正常标题，建议使用明确的失败表述。删除全部并保存表示不检查失败关键词，其他响应校验仍生效。

关键词独立保存到 SQLite，无需重启；恢复默认只更新草稿，仍需点击“保存失败关键词”。新建的手动、计划或失败重试批次冻结当时的规则，同批次主模型、重试和兜底共用；已创建批次不受之后编辑影响。关键词只用于程序判定，不会自动改写或附加到模型提示词。

## Web 抽帧设置

「系统设置 → 抽帧设置」统一管理抽帧策略、最大帧数、首尾跳过比例、时长/大小档位、图片最长边和 JPEG 质量。设置保存到 SQLite，不写回 YAML。

默认按视频时长（duration），最多 32 帧，首尾各跳过 5%，图片最长边 768 像素，JPEG 质量 4。最大帧数和每档帧数为 1–32；首尾跳过比例之和小于 100%；最长边 128–2048 像素；JPEG 质量 2–15（越小通常越清晰）。

时长档位默认为 30s/8 帧、2m/12 帧、10m/24 帧、30m/32 帧，其余 32 帧；大小档位为 50MiB/3 帧、200MiB/5 帧、1024MiB/8 帧，其余 12 帧。上限严格递增，末档固定覆盖其余范围。时长输入支持 30s、2m、1h。混合策略按时长为主，大小辅助最多增加 2 帧；实际帧数同时受最大帧数和有效采样窗口长度限制。

内置默认值用于尚未保存抽帧设置的实例；已保存的设置继续生效，不随程序默认值变更而覆盖。

手动运行、自动计划和失败重试创建批次时，读取当前设置并保存快照。保存新设置立即作用于以后创建的批次，已有批次使用创建时的抽帧和图片参数。

## 系统资源设置

「系统设置 → 处理与缓存」保存抽帧并发数（默认 8，1–32）与临时缓存容量（默认 10 GB，1–10000，1 GB = 10^9 字节）。两者保存到 SQLite，不写回 YAML。模型并发仅控制请求，按模型配置跨批次共享；抽帧并发全局共享。

`tmp-storage: "../.cache"` 与 storage 一样按配置文件目录解析，显式空值无效，路径不得通过符号链接落入媒体根。程序使用其下专属 `video-rename-frames-v1/`；该受管目录不能是符号链接，媒体、配置文件/目录、storage 及数据库真实路径不能落入其中，启动时会在任何建库或缓存清理前拒绝危险重叠。缓存父目录仍可包含彼此独立的媒体与持久数据目录。缓存默认闲置72小时自动清理、成功改名立即删除；可在页面调整为延时或保留，或关闭闲置清理。失败/取消保留完整缓存。容量不足先淘汰闲置旧缓存，保护使用中的截图；降低容量时正在使用的空间可能暂时超出新上限，任务释放后自动收敛。

「处理与缓存」还提供批次调度容量：同时运行批次默认 32 个（1–256），等待批次默认 1000 个（1–100000）。设置保存到 SQLite，后续调度与提交读取最新值，无需重启。扫描、运行、已开始后暂停及取消收尾占运行名额；排队和未开始就暂停的批次占等待容量。等待满额时拒绝新提交；降低上限不取消或删除已有批次，运行数降到上限以下才启动后续批次。调高批次容量不改变抽帧和模型各自的并发上限，也不保证吞吐同比增加。

「处理与缓存」还提供“文件稳定性检查”：等待时长默认 30 秒，范围 0–3600 整数秒，0 禁用等待。设置保存到 SQLite，刷新与重启保留；后续开始的批次读取新值，已有批次保持开始时读取的时长。禁用等待不关闭处理前、模型请求前和改名前的文件变化核对。
