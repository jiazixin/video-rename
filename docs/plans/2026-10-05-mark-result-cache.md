# 标记任务结果缓存修复 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 连续标记或取消标记不再因完成结果缓存达到 128 条而等待一小时，断线重试不重复执行旧操作。

**Architecture:** 后台任务仍串行执行，完成结果最多保留一小时；容量满时回收最早完成的结果，继续接受新操作。前端只用 POST 启动新操作，已有请求一律 GET 查询；结果被回收、过期或服务重启后，要求重新选择目标，不能自动重放。

**Tech Stack:** Go 1.27.1、Vue / TypeScript、SQLite、Playwright。

---

用户已授权直接实现并完成测试。沿用当前工作区与数据库结构，不迁移目录或调整依赖。

## 设计选择

- 采用有界终态缓存回收与只读重试：保留断连查询能力，也能继续新操作。
- 单纯取消容量上限会让结果缓存随操作增长；不采用。
- 持久化全部任务键可扩大结果留存与服务端防重放范围，但需要改变数据库协议；本次没有这项需求。

结果缓存不是永久幂等账本：仅在结果仍保留时，同键 POST 返回原任务；已有请求重试必须 GET。回收任务结果不删除数据库中的文件标记和改名历史。

## Task 1: 后端缓存与回归

**Files:** 修改 `internal/app/mark_jobs.go` 与 `internal/app/mark_jobs_test.go`。

1. 增加测试：连续超过 128 次真实标记/取消仍成功；满缓存时回收最早完成项；同键仍复用原计数；活动任务不被回收；状态过期只影响查询，不影响持久标记。
2. 先运行新增测试，确认旧实现因 HTTP 429 或结果未回收而失败。
3. 以命名常量定义结果容量与保留时间，移除缓存满的 HTTP 429；先查同键和活动任务，再回收最早终态并接纳新请求；状态查询删除已过期结果。
4. 运行标记任务测试及受影响包竞态测试。

## Task 2: 前端重试与提示

**Files:** 修改 `web/src/app/api.ts`、`web/src/features/library/Library.vue`、相关 `web/e2e/` 用例。

1. API 错误保留 HTTP 状态，已有请求只查询原状态。
2. 明确的应用拒绝（400/401/403/409/429）允许下次使用新键；网络失败、5xx 和响应未知保留原键只查询。
3. 结果失效时禁用原弹窗确认，提示关闭并重新选择；区分未启动、查询失败、任务中断和文件失败。
4. 浏览器回归覆盖首次响应丢失、轮询丢失、5xx 未知结果、明确拒绝后重试、失效不重放及跨批次重试。
