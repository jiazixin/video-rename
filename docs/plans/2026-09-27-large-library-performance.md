# 大规模媒体库性能优化

## 场景与边界

Linux 服务，本地 SQLite 与截图缓存，媒体位于 CIFS 挂载；总文件数几十万，实际数据库约 1 GB。此前本地小库入队测试不能代表生产端到端延迟。继续使用 SQLite，保留标记、历史与文件身份校验的业务行为。按未上线项目约定只维护当前完整结构，不保留旧库兼容或迁移分支，不操作用户实际数据。

## 实施与验证

1. 构造 300,000 文件索引、目录层级、处理标记与历史记录，测量目录页统计和提交相关查询；记录数据集与本机限制。
2. 增加最多 4 个只读连接，写连接保持 1 个；重查询及只读事务显式走读池。验证写事务期间可读、读快照期间可写、读池禁止写入、关闭与重开。
3. 同一响应合并目录统计，仅遍历所选目录覆盖的子树一次，数据库按目录聚合再汇总祖先；不增加跨请求过期缓存。验证重叠目录、未索引/失败、标记、任务状态及取消。
4. 路径核验只读取基础索引；从一次文件信息读取生成身份快照，减少 CIFS 重复调用。保持符号链接、挂载和快照保护。
5. 检查任务扫描的逐文件提交，将已读取的文件候选按有界批次写入；文件访问放在事务外，失败与取消回滚当前批次。
6. 完整 Go 测试、race、vet、构建、Linux 编译，以及大规模合成数据回归。明确真实 CIFS 和生产数据库未测试，保留扫描与改名互斥保证。

## 取舍

采用读写分离、请求内合并和短事务。直接更换 MySQL 无法解决重复遍历和 CIFS 等待；持久化统计缓存需要额外失效协议，本次先保证读取最新已提交状态。扫描与改名的互斥锁涉及文件安全，不直接移除。


## 已完成与结果

- 实现 1 写连接 + 最多 4 个只读连接，重查询改走读池。
- 同一响应合并进度统计，轻量读取文件快照，复用文件信息减少 stat，候选按 128 项事务写入。
- 3 个性能索引直接并入完整建表结构：目录 parent/id 游标、目录条目 dir/entry 更新、自动命名失败记录按 entry 清理；结构标识为 20260929，旧结构拒绝启动，不自动补建索引。
- 30 万文件、约 908 MiB 合成库的目录统计约 2.9 秒 → 0.97 秒；单目录候选分页落库在补游标索引前约 148 秒，之后约 3.1–3.3 秒。详见 `docs/IMPLEMENTATION.md` 的数据集、命令与边界。
- 完整 Go/race、vet、构建、Linux 编译、7 项浏览器回归、两目录 2 万标记断连恢复均通过。真实 CIFS、代理和生产数据库未测；扫描与修改的互斥锁仍保留。
