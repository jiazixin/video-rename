# 目录局部更新与处理标记实施计划

目标：自动命名后保留列表位置；支持视频、跨页多选与目录递归标记/取消已处理。
架构：复用 SQLite marks，允许无关联改名操作的 marked 来源。目录扫描复用 library.Refresh；逐文件校验身份并与改名使用同一锁。活动任务中的目标拒绝修改标记并报告失败。只处理已有视频，不给目录持久排除属性。
技术栈：Go、SQLite、Vue、TypeScript、Playwright。

1. 存储与 library：迁移 marks.operation 为可空；添加递归标记结果统计与逐项失败；保留原改名历史。验证硬链接去重、内容变化、重启、目录新增文件、取消标记与还原。
2. HTTP：受现有会话/CSRF 保护的标记接口，以及按 ID 读取条目快照接口；限制单次目标数并校验输入。
3. 列表：改名原位维护分页索引；前端轮询条目快照和已提交任务状态，避免空列表、重排与全局 busy。导航时丢弃旧响应，错误可重试。
4. 界面：单项和批量标记弹窗，说明递归范围、仅改状态、数据库丢失需重做；保留选择，反馈部分失败。
5. 验证：Go 单元/HTTP/任务测试、类型检查与构建、隔离 Playwright 回归；更新 README 和开发说明。当前无 Git 元数据，不创建提交。

追加范围：目录行和当前目录显示递归处理汇总（待处理、部分已处理、全部已处理，附数量）。未完整索引时显示待统计，无视频时显示暂无视频。汇总仅使用数据库最近扫描结果，不在浏览时全盘扫描。

验证记录（2026-09-21）：前端类型检查/构建、Go 全量测试与 vet 通过；library/jobs/app/storage 竞态测试通过。21 个浏览器用例分组通过，包含真实 FFmpeg 自动命名、手动改名/还原、批量标记/取消、目录汇总、局部更新与窄屏。整套连续运行第 16 项触发原有登录限流，剩余 6 项在新隔离实例通过；未改变生产限流。测试均使用临时媒体/数据库与假模型，未操作真实媒体或重启用户服务。
