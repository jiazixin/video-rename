# 扫描性能、布局与目录状态筛选实施计划

**目标：** 减少后台扫描重复开销，重新组织扫描设置与进度布局，让文件和目录都响应处理状态筛选。

**架构：** 沿用独立扫描协调器和每目录稳定性发布；先测量再优化单轮暂存和目录遍历。目录筛选使用同一只读快照中的递归视频汇总参与计数和分页，前端保序更新采用服务端筛选结果，避免重新插入已过滤目录。

**技术栈：** Go 1.27.1、SQLite、Vue 3 / TypeScript、Playwright，使用项目原生命令。

## 已确定的设计

- 用户明确选择目录也参与筛选：未处理隐藏内部视频已全部处理的目录，尚未完成索引的目录保留为待统计；细分状态按递归视频匹配。
- 设置页采用紧凑的启用 / 间隔控制和整行扫描范围，范围列表的名称、状态和进入操作分列对齐。
- 扫描状态采用稳定结构显示阶段、耗时、目录 / 文件累计数量、变更计数和当前路径；不显示无法准确计算的百分比。长路径单行截断并可查看完整路径。
- 沿用现有工作台主题和字体，只调整受影响区域；取消、失败、窄屏和未保存设置继续可操作。
- 继续保持两遍属性读取、目录身份 / epoch 核验、取消与失败保护、批量短事务及 FULL 同步。

## 实施与验证

1. `internal/library`、`internal/libraryscan`：测量多目录扫描，优化暂存复用和子目录遍历，补取消 / 失败 / 结果一致性回归。
2. `internal/library/processing_status.go`、`progress.go`、`library.go`：修正目录筛选，统一匹配、总数和分页，补混合状态、未索引目录和来源状态回归。
3. `web/src/features/library`：重排扫描设置、范围选择和状态卡，修复静默更新重新插入已过滤目录的行为，添加筛选范围说明。
4. `web/e2e/library-status.spec.ts`、`library-scan.spec.ts`：验证目录隐藏 / 标记后变化、分页与返回状态；验证扫描中长路径和不同终态的桌面 / 窄屏布局。
5. 格式检查、TypeScript 检查、Web 构建后执行 Go 测试 / race / vet / 模块校验和服务构建，再运行隔离浏览器测试。文档记录实际性能与未验证的 NAS 吞吐。
