# 抽帧流水线与系统设置实施计划

目标：跨批次独立调度抽帧和模型调用，截图可重用，设置集中管理。

架构：Go 单实例内维护全局抽帧限额及每模型并发限额。截图放 tmp-storage 专属子目录，用源文件快照和抽帧设置哈希映射，清单原子落盘。SQLite 保存系统设置，Vue 系统设置页聚合处理与缓存、模型、抽帧、通知。

技术：现有 Go / SQLite / Vue，不增加依赖。

## 已确定决定

- 抽帧默认并发 8，缓存默认 10 GB（十进制），3 天未使用自动清理。
- 抽完单个视频即可进入模型队列，不等待整组。运行批次保留用于结果和取消。
- 成功提交改名后删除缓存；失败与取消保留完整缓存，丢弃不完整输出。
- 文件身份、大小、mtime 或抽帧参数变化使旧缓存失效；模型和提示词变化不影响截图复用。
- 缓存有占用租约，使用中的截图不能被清理；满额先淘汰闲置旧缓存，再等待。抽帧预留工作空间，失败释放。
- tmp-storage 相对配置文件解析，默认 ../.cache；只维护其下专属缓存目录。配置不得指向媒体根内。
- 并行运行批次，上限沿用 20 个活动运行；模型并发跨批次共享。取消只影响对应批次，普通单文件失败不取消其他文件。

## 步骤

1. config 增加 tmp-storage；storage migration 与 internal/systemsettings 增加验证和持久化。
2. internal/framecache 实现加载、映射、租约、容量预约、过期和淘汰，覆盖重启复用、失效、占用保护、取消等待测试。
3. pipeline 拆出 Prepare 与 Infer；jobs 增加分阶段限额、跨运行调度和成功提交后释放，保持文件稳定性检查和诊断。
4. app 增加认证保护下的设置接口；web 设置页聚合现有功能，更新导航与浏览器测试。
5. 运行 npm --prefix web run build、go test ./...、go test -race ./...、go vet ./... 和相关集成、浏览器测试；更新 README 与开发文档。

## 取舍

单纯增加模型并发无法独立预取截图；一次性抽完全部视频会增加磁盘压力。采用有界流水线，容量不足时暂停生产。缓存属于可重建数据，服务崩溃后保留完整结果，不自动续跑原批次。
