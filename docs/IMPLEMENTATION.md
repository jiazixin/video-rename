# 开发与实现

当前应用为 Go 1.27.1 + Vue / TypeScript + SQLite 单实例 Web 服务。当前使用协议见根 README 与 [运行说明](operations.md)。

## 边界

- `internal/app`：HTTP 路由、中间件装配、静态资源和生命周期。
- `internal/auth`：随机令牌、哈希会话、12 小时滑动过期（活跃自动续期）、CSRF、同源校验、登录限流。
- `internal/storage`：SQLite schema、WAL、FULL 同步、单写连接与最多 4 个只读连接、实例锁。
- `internal/library`：根约束、文件身份、目录索引、统一改名与恢复。
- `internal/models`：模型配置、服务预设、密钥编辑、模型检测、不可变运行快照。
- `internal/jobs`：磁盘候选、运行状态、动态并发调度、取消及去重。
- `internal/scheduler`：五段 Cron、显式时区、预览、唯一触发与重启不补跑。
- `internal/pipeline/stages.go`：探测、抽帧和模型推理阶段，由 jobs 调度，文件提交统一交给 library。
- `web/src/features`：认证、目录、历史、运行、模型、提示词、统计与设置等业务域；目录选择器通过 library 的公开入口供运行页面复用。

数据库表结构以 `internal/storage/schema.sql` 为唯一建表入口，`schema.go` 在空数据库内事务创建完整结构；只接受当前结构标识，不提供旧数据库升级或导入。已有不支持的数据库启动时报错，需要配置新的 storage 目录，原数据不重建、不清空。实体 ID 使用 AUTOINCREMENT，避免删除后复用 ID 导致历史快照、计划去重或分页关联错误。外键、FULL 同步及 busy_timeout 随每次连接建立启用，提示词引用由数据库外键和业务检查共同保护。模型密钥与运行配置快照加密保存，API 只返回脱敏摘要，见 [模型配置](models.md)。

三个性能索引直接定义在 `internal/storage/schema.sql` 中，分别支持目录按 parent/id 游标扫描、按 dir/entry 更新已改名文件，以及按 entry 清理自动命名旧失败记录。当前结构标识为 `20260929`，只在空数据库中创建完整结构；不提供旧结构补索引或升级分支。

`Store.Read()` 显式提供只读池，连接同时设置 `mode=ro` 和 `query_only`，沿用外键和 busy timeout。目录读取、历史、批次分页与分析使用读池；修改和读后写事务仍走单写连接。多个相关统计在同一只读事务中读取，保持一致快照；关闭 Store 时先关闭读池再关闭写池。

## 构建顺序

```bash
npm --prefix web ci
npm --prefix web run build
go build -o bin/video-rename ./cmd/video-rename
```

`web/embed.go` 直接嵌入 `web/dist`。不复制资源到后端目录，不提交占位 HTML 绕过嵌入检查。`web/dist`、`bin` 和测试产物均忽略。

媒体和模型底层测试与 jobs 集成测试覆盖当前处理链，浏览器测试验证 Web 入口。

## 目录多选与播放

分页导航在 `web/src/components/PageNavigation.vue` 统一实现，覆盖文件目录、目录选择器、运行记录、抽帧记录、批次列表和文件详情、两类统计明细及两类编号预览。目录选择器使用已有 page 参数；运行记录新增 page，抽帧记录新增 success_page / failure_page，批次文件详情新增 page（每页 100 项，返回 items/total/page）。这些接口先在同一读事务内计数、收敛页码再计算 OFFSET；旧游标查询供其他现有调用使用。跳页直接请求目标页，不逐页遍历；前端保留原筛选、排序和各页面既有选择规则。

批量删除在确认时冻结所选条目的 ID、名称和版本，列出跨页目标及目录递归删除提示。逐项调用已有 DELETE 接口，沿用版本、身份及活动任务校验，不提供整批回滚。成功项移出选择，失败项保留并显示原因；完成后刷新当前目录，沿用有效页码收敛。删除按钮位于清空和抽帧之间，以红色和两侧竖线单独区分。

目录页多选按当前目录保存跨页 ID；本页全选 / 反选不加载其他页。自动命名复用运行 API，每批最多 100 个目标，服务端继续执行范围和重复校验。批量还原复用逐项恢复 API，保留失败项，不提供跨文件事务回滚。

多选模式下，普通点击复选框切换单项并记录起点；Shift 点击按当前页显示顺序选中起点到目标之间的所有可选条目，包含两端，支持反向选择，保留范围外和其他页的选择。连续 Shift 点击沿用起点；没有有效起点时按普通单选处理。切换目录、页码、搜索、类型、排序、每页数量、多选模式，以及主动刷新、全选、反选、清空时重置起点；后台原位更新保留起点。

后台目录刷新按 ID 查询现有行的最新状态并原位更新，移除已不存在的条目，仅在本页有空位时追加新条目，保留阅读位置和勾选；没有勾选时也保持已有行顺序。主动刷新、翻页和筛选使用最新列表，刷新完成前的后续轮询也沿用主动重排语义。

返回目录时按目录 ID 恢复页码、搜索、类型、排序和每页条数，优先将此前进入的子目录居中并高亮，找不到该行时恢复原滚动位置。位置记录在当前页面会话内保留；列表快照独立限制为最近离开的 30 个目录，淘汰快照不删除位置记录，无快照时按保存页码重新请求并在渲染后定位。整页刷新会清空这些内存记录，地址栏只恢复目录 ID。浏览器回归覆盖连续进入超过 30 个子目录，以及父目录快照被淘汰后的返回定位。

目录页通过 `GET /api/directories/{id}/entries?page=N` 按页码读取，总数、目录 generation 和本页 ID 在同一个只读事务中查询；事务结束后再读取条目实时状态，避免嵌套占用只读连接池。页码先收敛到有效范围再计算 SQL OFFSET，目录缩小时停在最后一个有效页，空目录为第一页。后台扫描完成不使页码请求失效，刷新和删除保留页码，搜索、排序和每页数量改变重置到第一页。未传 page 的调用仍使用原有 generation + 游标协议及版本校验，供媒体遍历和目录选择等调用方使用。深页查询仍有 OFFSET 成本，不加载整个目录到浏览器。回归见 `internal/library/pagination_test.go` 和 `web/e2e/library-pagination.spec.ts`。

多选命名 / 抽帧提交每组目标后显示对应批次编号；全部入队即释放提交状态，列表状态刷新在后台进行，不因慢速查询继续锁住操作。创建阶段的目标去重和批次重叠检查共用仅本次请求有效的轻量祖先缓存，每个目标与祖先条目最多查询一次基础字段，不重复加载运行状态、命名历史或扫描目录内容。保留递归父目录覆盖、非递归只覆盖直接文件、文件硬链接冲突以及请求键幂等校验。提交只校验数据库中的目标类型、关系和配置；真实媒体路径与祖先身份的校验移到 worker，全部目标通过后才扫描生成条目。挂载失效、文件缺失或被替换在批次中报告失败，处理和改名阶段仍保留原快照校验。性能回归：`go test -tags=scale ./internal/jobs -run 'TestScale(MultiSelect|MixedDirectory)Submission' -v`。

`GET /api/entries/{id}/video`、`/audio` 与 `/image` 预览经过会话认证；library 以受根目录约束的文件描述符打开、核对文件身份和祖先路径，HTTP 层使用 ServeContent 提供 Range / seek，不把整段媒体文件读入内存。音频按扩展名固定 Content-Type，避免各平台探测不一致。不提供转码。播放器关闭时暂停、移除 src 并释放资源。共享 Modal 使用引用计数锁定页面滚动，最后一个弹窗关闭后恢复原有样式。

## 原位更新、处理标记与目录汇总

marks.operation 可空，手动状态标记使用 source=marked、operation=NULL；不创建伪改名历史。取消标记删除对应文件身份/大小/修改时间的保护，不撤销操作历史。

POST /api/entries/processed 接收 targets（1–100）和 marked，递归扫描现有目录，逐视频核对路径与快照，使用 library 的改名互斥锁修改标记。重复/重叠目标去重；返回 changed、unchanged、failed 和最多 100 条错误详情。活动任务中的文件不允许修改标记。新视频与内容变化后的文件不继承标记，硬链接共享身份标记。

页面同时提交 key，将标记交给应用生命周期内的后台任务，接口立即返回 202；`GET /api/entries/processed/status/{key}` 每秒查询已提交数量和状态，避免大目录长请求因反向代理超时而中断。相同 key 与参数返回原任务，网络失败后重试沿用 key；不同参数复用 key 返回 409。后台同一时间只执行一个标记任务，防止多页面标记/取消交错。状态查询沿用登录和 no-store，写入沿用 CSRF。未带 key 的调用保留同步返回。

标记结果逐文件持久化；任务进度只在进程内保留，终态保留一小时，最多 128 个记录。页面断连或关闭不取消已提交的后台任务；服务关闭会取消并等待任务退出，中断状态不会当作全部完成。重启后进度查询明确提示重新选择目标重试，已写入的标记继续保留，不增加数据库结构或要求清空旧标记。大规模回归命令：`go test -tags=scale ./internal/library -run '^TestScaleProcessedMarks$' -v` 与 `go test -tags=scale ./internal/app -run '^TestScaleBackgroundMarksDisconnected$' -v`，后者覆盖两个目录共 20,000 个视频、提交请求取消后完整落库。

GET /api/entries/status?ids=... 返回最多 300 个条目的当前状态（不存在的条目省略），不会启动目录刷新。前端按 ID 合并，不重排；运行从排队到终态持续查询，避免扫描前尚无 run_items 时停止轮询。导航及更新请求序号阻止迟到响应覆盖新页面。成功改名原位维护 directory_items 名称，不清空分页索引。

目录页和条目状态接口使用 `WithProgressBatch`，在一次可取消的只读事务中统计所请求子树的并集；递归只遍历目录，视频标记和活动状态在 SQL 内按目录聚合，再向父目录汇总。重叠父子目录共享结果，只传输目录级计数，不逐文件返回数据库行；不使用跨请求过期缓存。媒体分类复用现有扩展名规则注册的确定性 SQLite 函数。

目录 progress 汇总 SQLite 中当前可达的完整子树：total、processed、unknown（未完整索引/扫描失败目录）、active。手动与自动命名、手动状态标记均计入 processed。unknown 非零时不宣称全部已处理；汇总不触发全库磁盘扫描，外部变更在目录扫描后反映。

目录内容列与递归处理进度分别计算：只读取 `directory_state` 当前完整 generation 对应的 `directory_items`，统计该目录的直接子目录、视频、图片和音频（`contents.audio`）；未索引或扫描报错时返回空统计状态，前端显示“待统计”。扫描进行中保留上一次完整索引的数字，完成后由目录列表刷新更新。`DirectoryContents.vue` 在目录行中呈现两行两列紧凑统计，仅显示图标及等宽数字，类型名称由悬停提示与无障碍标签提供；刷新按钮前使用 `inline` 模式，单行显示图标、类型文字和数量。统计不受分页、搜索或类型筛选影响。

目录扫描每批最多读取 128 个条目的文件信息，再开启数据库事务写入该批，避免 CIFS 等慢速媒体挂载在读取元数据期间占用 SQLite 唯一连接、拖慢任务提交和状态查询。扫描仍持有 library 的修改互斥锁，文件身份核验和完整 generation 发布规则保持不变；元数据读取失败或取消时，不写入当前不完整批次、不将遗漏条目标为消失，也不发布未完成的 generation。回归测试 `TestRefreshSlowMetadataLeavesDatabaseAvailable` 模拟阻塞的文件信息读取，验证数据库读写仍可进行；`TestRefreshMetadataFailureKeepsCompleteGeneration` 覆盖读取失败、取消和随后重试。这些测试不代表真实 CIFS 环境下的端到端提交耗时。

## 递归目录编号

目录顶部编号通过 `POST /api/directories/{id}/numberings/tree-preview` 刷新并遍历真实目录树，忽略符号链接；按文件夹创建包含图片和音频的 `mixed` 编号预览，沿用既有日志、冲突检测、两阶段改名及还原。图片和音频分别使用保存的规则，共用序号时音频规划使用图片的目标名称预留号码。右上角编号页面使用下述短请求任务接口，后端按父目录在前的顺序调用编号执行逻辑，避免子目录内改名造成父目录预览指纹失效；失败停止后续目录并显示已完成数量。`GET /api/directories/{id}/numberings/tree` 汇总当前可达子树最近 100 次编号操作，供刷新后还原及异常恢复。

编号预览与扫描继续共用 `Library.mu`，不再用后台刷新标记额外拒绝预览；该标记可能代表排队中的扫描或已完成但尚未清理的 worker。预览仍检查完整索引、文件身份与前后目录指纹，应用前再次核验。大小写冲突检查一次读取真实目录条目并按文件名分组：目标有精确同名条目时，必须是本次待改名源且身份、大小、修改时间匹配；目标无独立条目时，仅接受唯一的大小写匹配待改名源，且目标路径的大小与修改时间一致。这个预览分支允许大小写别名返回不同 inode，避免直接把别名判为外部占用。大小写有歧义、未参与文件、目录和符号链接仍拒绝。应用、临时改名、最终提交和恢复继续核验文件身份，并使用 no-replace 改名。

编号失败通过 `numberingFailure` 保留包装错误中的 `JobError.ProcessingLog`，返回 `processing_log` 并写入进程默认错误输出（`numbering failed`）；编号弹窗展示折叠详情与复制按钮。目标冲突诊断含目录、原名、目标名、目标类型、文件身份和占用条目是否参与本次编号。原有源文件变化诊断保留，视频处理日志仍在运行/抽帧记录。预览失败不会产生已执行编号记录；已执行批次的持久化移动日志仍保留用于还原及崩溃恢复。目录指纹与文件匹配复用单次不跟随符号链接的文件信息，避免对同一路径重复 stat；预览开始/结束及提交阶段的独立校验继续保留。冲突诊断复用失败检查中的目标信息和名称候选，只读取大小写匹配项；目录编号与媒体编号通过同一 `NumberingDiagnostics.vue` 展示和复制诊断。

## 固定命名失败协议

固定提示词默认要求标题不少于 25 个中文字符、建议 30–50 个中文字符，仅输出一个完整的单行中文标题。默认文本要求无法可靠命名时只回复“命名失败”；自定义文本按保存内容使用，恢复默认并保存后采用内置值。模型请求除固定提示词外不追加页面不可见的硬编码文本。

最终标题文本包含“命名失败”时，vision 返回非全局 NAMING_FAILED，交给 jobs 按批次重试策略处理；当次不进入文件名清洗或改名。复用任务失败处理：保留原文件名、不写已处理标记，写入任务历史失败记录及脱敏请求/响应；其他视频继续处理。

## 运行页面分区

批次记录通过 `GET /api/runs?category=all|manual|automatic&task=rename|extract&page=1&size=50` 获取分页，返回 `items/total/page/size/profiles`。task 留空表示全部任务。附加筛选为 `status`（原批次状态值）、`profile`（模型配置 ID，0 为无配置）、`from/to`（RFC3339，开始包含、结束不含）、`duration`（under1 / 1to5 / 5to30 / 30to60 / over60）。时间取实际开始时间，缺失回退提交时间；耗时按秒计算，不含排队，进行中取当前时间，缺少开始时间不匹配耗时区间。所有条件在同一读事务内先筛选、统计再取页；profiles 返回历史批次中的配置 ID 和名称，保留已删除配置的筛选能力。每页支持 50 / 100 / 200 条，页码越界收敛至最后一页。无 category 的列表接口继续供既有游标调用使用。页面显示总批次、页码和当前页条数；全部、手动、自动分别保存页码与条数设置，其他筛选切换重置页码，轮询和刷新保留当前页，切页与筛选请求通过序号防止迟到响应覆盖。

侧栏「运行管理」下的「计划管理」和「批次记录」分别使用 `#plans` 与 `#runs`。Runs.vue 按 view 分别展示计划管理或批次列表，切换时重新挂载，仅请求所属页面的数据。计划管理上半部分为手动计划（创建后立即提交一次批次），下半部分为持久化自动计划；两个创建弹窗均提供命名 / 抽帧类型。schedules.task 区分 rename 与 extract；抽帧计划保存 model_config_id=0，跳过模型校验，定时触发与立即运行均传递 task。批次页顶部统一提供组合筛选。source=schedule 或 plan>0 的运行归计划触发，包含计划卡片上的立即运行；其余归手动运行。记录按批次编号倒序分页。

运行中批次的预计剩余时间是纯前端估算（Runs.vue 的 trackEta），不新增接口或轮询频率：每次既有 3 秒轮询用已处理增量（done+skipped+failed）计算瞬时速率并做 EMA 平滑（α=0.3），无增量的轮询保留上次有效速率；首次看到 running 状态的轮询作为基线，回退平均速率与预热均基于该基线的差值，避免扫描期瞬时跳过项抬高速度。预热条件为处理差值达到 warmup 阈值（总数≤2 恒不显示；3–10 取 max(2, ⌈总数/2⌉)；>10 取 10）、running 超 5 秒且存在有效速率，满足前显示“预计时间计算中…”。批次离开 running 状态即停止估算并清理状态；移动端窄屏隐藏剩余时间片段。

目录选择器与文件目录页共用 library/DirectoryStatus.vue，显示递归处理状态、已处理/总数及活动数量；保留待统计状态与原有多选、层级、分页行为。

## 批次通知与诊断扩展

notification_channels 保存渠道，notification_deliveries 保存发送队列，runs.started 记录实际开始时刻。独立 notifications worker 每 3 秒发现新终态批次、持久化通知并发送；每渠道/批次唯一键去重，启动恢复 sending 为 pending，失败最多三次（30 秒、60 秒退避）。关闭配置取消待发送项；重新启用从最新批次 ID 开始。通知失败不修改任务状态。HTTP 禁止重定向，限制响应 64 KiB，校验渠道业务码，错误文本不回显远端正文或含密钥 URL。

operations 保存脱敏请求/响应，run_items.original_path 保存原始路径。成功模型结果经 pipeline 捕获后与 prepared 操作一起持久化，完成或崩溃恢复时写入成功事件，诊断接口支持成功与失败记录。图片负载省略、凭据脱敏、每项 128 KiB 限制沿用既有实现。GET /api/runs/{id} 返回目标显示路径，items 返回原始与当前路径，详情支持每页 100 项翻页。

## 目录排序与时间

重命名时间来自该条目最近一次 committed 操作的 created 时间，包含手动、自动命名和还原；处理标记、失败操作与外部改名不计入，没有记录显示“—”。操作记录与展示历史分开，因此清空任务历史不会清除此时间。原文件 mtime 继续显示为“文件修改时间”。

## 排队范围占用

## 通知时区与上下文诊断

notification_preferences.timezone 保存通知时区。认证完成后浏览器提交 IANA 时区，后台生成新通知时按此时区转换，包含 UTC 偏移和时区名称；关闭浏览器或服务重启后沿用已保存设置。未同步前默认为 UTC，已经生成的通知正文保留原值。程序内嵌 tzdata，容器缺少系统时区文件时仍可转换。

新请求诊断在本地脱敏副本的 _local_context 中保存请求字节数、图片张数、输出上限及文字 Token 粗估（ASCII 字符数 / 4，其他字符数 × 1.5）。该元数据不发送给模型，也不额外请求计数接口。文字估算不含图片与协议开销，不代表完整上下文；自定义模型需其 tokenizer 和图像处理规则才能准确计算。诊断面板优先展示响应 usage 的实际输入 Token，Anthropic 输入包含缓存读写；1K = 1000 Token，KiB 为 1024 字节。

## 目录编号短请求与取消

右上角编号入口通过 POST /api/numbering/jobs 提交 preview 或 apply，立即返回 202 和请求键；重复键与相同参数返回原状态，参数不匹配返回 409。预览阶段只生成计划，仍需用户点击确认后提交 apply；确认整棵目录树仅提交预览任务键，由服务端读取冻结的目录顺序，避免大目录清单超过请求体限制。GET /api/numbering/jobs/{key} 返回扫描目录、文件数和执行目录/文件进度，同时续租；GET /api/numbering/jobs/{key}/result?offset=0 返回目录摘要和最多 100 条文件明细。列表不再一次接收整棵目录树的所有条目。

处理中点击关闭按钮、遮罩或按 Esc 会先显示取消确认，默认聚焦“继续处理”，确认期间保持进度查询。确认停止、切换页面或浏览器 pagehide 时前端中止查询并使用 keepalive 发送 POST /api/numbering/jobs/{key}/cancel。取消请求先于提交到达时也会保留取消标记，迟到提交不会启动。超过 20 秒未查询进度时服务端自动取消，避免关闭浏览器或断网后持续执行。任务在应用生命周期内运行但受独立取消上下文约束；同一时间只执行一项编号任务。状态保留一小时，最多 64 项，进程重启不自动续跑。

预览循环和写入事务检查取消；执行在逐项核验、两阶段移动及提交前检查取消，沿用持久化日志安全回滚当前目录。回滚本身不被取消，失败时保持 review 并提示核对；已经提交的目录保留，后续目录不执行。单次底层文件系统调用无法强制中断，返回后继续处理取消。服务关闭会取消任务并等待安全退出后关闭数据库。任务错误仍保留 processing_log 供弹窗显示和复制。

## 图片与音频一键编号

系统设置的编号规则页使用图片 / 音频切换，分别编辑命名前缀、最小位数、编号方式与扩展名大小写，并实时显示文件名格式示例（实际号码以编号预览为准）。共用序号独立放在公共设置中；切换类型保留未保存草稿，底部统一保存两种类型并显示修改状态。详细匹配与保留号码语义收在“规则说明”，窄屏采用单列布局。

image_numberings 和 image_numbering_items 保存编号批次及条目，media 列区分图片与音频批次，两类共用同一套移动日志与崩溃恢复机制，编号记录按类型分开查询。system_settings.numbering 以 JSON 保存编号规则（最小位数、前缀、扩展名小写、紧凑重排、图片音频共用序号），空值使用内置默认，存储错误或非法 JSON 明确报错；`GET/PUT /api/numbering/settings` 读写，预览时读取当前规则并把最终文件名冻结进批次条目，应用与整批还原不依赖之后的规则修改。接口为 `POST /api/directories/{id}/numberings/preview`（body 指定 media）、`GET /api/directories/{id}/numberings?media=` 与 `/api/numberings/{id}` 下的 apply / restore-preview / recover。服务端复用目录排序表达式，读取完整当前目录索引，按搜索过滤所选类型文件，冻结预览中的文件身份、版本、原名、新名及目录指纹；确认时重新校验。编号为正整数，前导零规范化，0 和非纯数字名称进入续排；使用大整数避免长数字溢出。不同格式共用序号，未参与的编号文件保留其号码。硬链接重复参与时拒绝操作。

修改项先全部转唯一临时名，再转最终名。每次移动前写入 pending_name，使用平台 no-replace 改名并同步目录后记录 current_name。最终在单一数据库事务中提交索引、原名到最终名的历史以及批次状态；临时名不出现在历史中。数据库提交结果不确定时先查持久状态，不盲目回滚。中断批次在启动时依据文件身份与 current/pending 证据做两阶段回滚；证据不一致或原名被外部文件占用时标记 review，阻止相关范围改名和扫描，用户可在编号记录中重试恢复。

编号记录显示当前目录最近 50 次已执行操作。整批还原先预览，要求每张改动图片仍对应原批次操作且未发生后续改名或内容变化，恢复原名及扩展名原始大小写；使用同一持久化移动机制。预览无文件修改，过期预览按日清理；已执行日志保留。接口统一走登录和 CSRF 校验，应用请求只提交服务端预览 ID，不接受客户端指定任意目标文件或名字。

## 系统设置与抽帧缓存

系统设置集中提供处理与缓存、编号规则、Prompt配置、模型配置、抽帧设置和通知设置。system_settings 保存抽帧并发（1–32，默认 8）与缓存上限（1–10000 GB，默认 10，十进制）。GET/PUT `/api/system/settings` 沿用登录、同源和 CSRF 校验。目录由 YAML `tmp-storage` 指定，默认 `../.cache`，相对配置文件解析。

jobs 同时运行最多 20 个活动批次，各自完成扫描与稳定性观察（默认 30 秒，可配置为 0 禁用等待）。抽帧调度在取得全局抽帧名额后派发，截图准备完成即释放抽帧名额，不再限制每批等待模型的视频数量；等待模型的截图持有缓存租约，以临时目录容量限制预取，容量不足等待释放后继续。全局抽帧限额与按模型配置 ID 共享的模型限额独立，排队不占用另一个阶段的槽位。配置降低并发时不打断已开始工作；模型其他参数仍使用任务快照。取消只停止对应运行，普通单视频失败记录后继续其余视频；全局依赖故障停止对应批次。

framecache 在 `tmp-storage/video-rename-frames-v1/` 中维护 SHA-256 键到截图清单的映射，键包含缓存版本、源文件 dev/inode/size/mtime、抽帧与图片参数，不包含模型或提示词。清单保存相对路径和内容校验和，原子替换；缓存目录有实例锁。完整输出在失败或取消后保留，文件与参数匹配且校验通过时重用；AutoCommit 成功后记录成功时间，由当前缓存策略决定立即删除、延时删除或保留。排队、请求与改名期间用租约保护截图。中断抽帧的半成品清理，重启清理遗留 pending 工作目录并加载完整清单，原批次仍标记 interrupted，需要用户重新运行。

容量计算包含每项清单预留 64 KiB；抽帧预约最大帧数 × 1 MiB 加 32 MiB 中间文件空间。媒体提取及时删除失败和重压缩原图。容量不足优先淘汰最久未使用的闲置缓存，全部占用时暂停生产；降低容量可能暂时低于正在使用的空间，后续释放后收敛。每分钟按已保存的策略清理到期闲置缓存，默认连续 72 小时未使用；启动加载清单前即传入策略，避免先按旧默认误删长时间保留的缓存。只管理专属目录中生成的缓存，媒体、配置和数据库不参与清理。

验证覆盖模型阻塞时单批 140 个视频全部提前抽帧（跨分页）、容量满后暂停及提交释放后的补位、等待容量时取消、跨批次预取与共享模型上限、失败/取消后复用、提交后删除、重启加载、缓存键失效、同尺寸内容损坏、容量等待取消、占用期间不清理、闲置淘汰、配置路径与鉴权，以及设置页桌面/窄屏和刷新持久化。

### 独立抽帧与统一记录

runs.task 区分 `rename` / `extract`，省略参数默认 `rename`；extraction_records 独立保存抽帧日志，提供状态分页与批次索引。`POST /api/runs` 的 `task: "extract"` 使用既有目标、递归、请求键、扫描、稳定性检查、全局抽帧并发和取消机制；忽略模型配置 ID、不读取模型或提示词，保存创建时的抽帧参数快照。相同请求键不能切换任务类型，抽帧和重命名的重叠范围统一互斥。

抽帧扫描包括已处理视频，完成后只释放缓存租约，保留截图，不创建改名操作或处理标记。手动抽帧和自动命名均调用 `jobs.prepareFrames`，按文件身份及参数取得缓存、校验抽帧后的源快照并记录结果。日志在准备阶段进入时写开始，在该阶段返回时写结束与毫秒耗时（包含缓存容量等待，不含批次扫描、稳定性观察、抽帧槽位排队和模型推理）；缓存命中保存 `cached=true` 及帧数。工具缺失、媒体失败等保存摘要与最多 128 KiB 诊断；取消记录失败原因，重启时将遗留 running 记录收尾为“服务重启，抽帧已中断”。后续推理或改名失败不会回写已经成功的抽帧记录。

- `GET /api/extractions`：`q` 搜索路径或失败原因，`run` 筛选批次，`from` / `to` 为 RFC3339 日期，`limit` 为 50 / 100 / 200；`success_before`、`failure_before` 是独立 ID 游标。单事务返回 `{success:{items,total,next},failure:{items,total,next},running}`；列表不加载诊断正文。
- `GET /api/extractions/{id}`：按需返回 `processing_log`。列表与详情均登录保护、`no-store`。
- `GET /api/logs/batches?category=extraction`：列出抽帧记录中的非零批次。
- `POST /api/extractions/clear`：`{all:true}` 清除已结束记录；沿用 CSRF 与同源校验，保留进行中记录和缓存。

## 本页选择、批次还原与媒体诊断

运行列表从创建时的 config_summary 显示模型 ID；任务历史通过事件的批次编号关联同一快照，手动操作不关联模型。运行批次的 token 数写入独立的 run_token_usage 表，每个视频的每次模型尝试分别记录可用诊断。优先取 usage.total_tokens，其次取输入与输出 usage 之和；缺失时回退到请求中的文字粗估。清除任务历史不影响新批次已保存的累计值。图片 Token 不包含在文字粗估中；每次重试或兜底请求使用实际模型配置记账。

目录选择器的全选、反选与取消仅修改当前分页的子目录 ID，保留当前目录和其他分页选择。运行记录统一显示还原批次、取消、详情；活动批次不能还原。POST `/api/runs/{id}/restore` 读取该批次所有成功自动改名的 operation，逐项调用原有 Restore 校验并提交，返回成功、已还原跳过、失败数量及最多 100 条失败详情。不会撤销后续改名或覆盖冲突文件；非跨文件事务，重复请求跳过已还原项，失败后可重新尝试。

events.processing_log 保存媒体诊断。抽帧失败保存每个时间点首次及补试错误、工具路径、视频流/尺寸、预算与最终摘要，日志有容量限制；ffprobe 的 stderr 同样持久化。诊断接口沿用登录与 no-store，详情默认折叠，按需加载并支持复制。设置页移除与页签重复的大标题。

## 用量分析

token_usage_records 是请求级用量账本：每条记录批次、run item、毫秒时间戳、token 数与估算标记；item 唯一键使写入幂等。批次累计仍写入 run_token_usage，两者在同一事务内推进，重复记录不会重复累计；无可计数的交换两端都不写。写入失败记录服务端错误日志，不影响改名结果。

GET /api/usage/analytics 在登录保护下聚合账本：`[from,to)` 半开区间（RFC3339，from 可省略表示全部），timezone 为 IANA 名称，model/profile/source/run 过滤，sort 支持 tokens/recent，分页最大 100。聚合在单个读事务内完成，总量、趋势、模型、配置、来源和批次排行共用同一过滤口径；模型身份来自运行创建时的 config_summary 快照，不随当前配置修改变化。趋势按区间跨度自动选 15 分钟 / 小时 / 天 / 月 / 年分桶，天及以上按请求时区的本地日历对齐（含夏令时）；"全部"从首条记录起算，避免空桶跨越数十年。批次行带区间内用量与来自累计表的全期用量两个口径。

前端 `web/src/features/usage/` 提供筛选行（预设区间、自定义日期时刻、模型 / 配置 / 来源 / 批次）、总览卡片、SVG 趋势图（悬停与方向键取值、完整数据表替代）、模型对比条、高消耗批次排行与分页明细；请求带中止与序号防迟到覆盖，错误提供重试。图表色 #0e8a5c / #0c7f52 已通过配色校验（浅色表面、色度与对比达标）。浏览器测试覆盖导航与直达、筛选参数往返、空态、错误重试与窄屏。

## 运行分析

run_items 保存 started_ms / finished_ms（毫秒，0 表示未记录）：jobs 在置 running 时写 started_ms，finish()、扫描期跳过与取消批量置状态时写 finished_ms；扫描前跳过的项只有完成时刻、不进耗时统计。

`internal/runstats` 聚合批次性能（结构与 tokenusage 平行：单读事务 + Go 内聚合 + 相同分桶粒度）：批次按实际开始（缺失用提交时间）归属 `[from,to)` 半开区间；批次耗时 = finished − started；逐项耗时 = finished_ms − started_ms（仅 done / failed 计入，cancelled 排除）；条目完成时刻取 finished_ms，未开始条目不进入耗时统计；P50 / P95 为 nearest-rank 分位；失败原因按首行截断 100 字符归组。`GET /api/runs/analytics`（字面路由优先于 `/api/runs/{id}` 通配）提供 from / to / timezone / profile / source / sort（recent / duration / size）/ page / size 参数，风格与 usage 接口一致。

侧栏「统计分析」分组提供 `#usage/tokens|analysis` 独立入口，由 App.vue 解析（默认 tokens）。`Usage.vue` 为页面标题和内容壳组件，按路由展示模型用量或运行分析，不再提供重复的页内导航；`UsageAnalysis.vue` 提供 10 格指标卡、批次耗时趋势、处理结果趋势（成功 #0e8a5c / 跳过 #2468af / 失败 #b14545，CVD 与对比校验通过）、吞吐趋势 + 耗时分布（单色顺序色带 ordinal 校验通过）并排、模型配置性能比较、`AnalysisScatter` 散点（最近点拾取 + 方向键）、失败分析与分页批次明细；图表组件 `AnalysisLine` / `AnalysisHistogram` / `AnalysisScatter` 沿用 UsageTrend 的悬停 / 键盘 / 数据表惯例，样式在 `analysis.css`。浏览器测试覆盖侧栏切换与 hash 直达、指标渲染、图表交互、排序筛选参数、空态、错误重试与窄屏截图。

## 一致性与失败处理

计划保存、删除和调度使用同一个互斥锁，避免 Tick 使用过期计划继续派发或覆盖新编辑；保存事务内重新检查模型引用。计划名称按 Unicode 字符计数，上限 80 字。模型设为默认时在事务内验证目标版本与受影响行数，失败整体回滚。

启动时在同一事务内收尾未结束批次及其排队/运行明细，写入中断原因与完成时间，避免详情和统计永久显示活动条目。PATCH 的资源 ID 必须是正整数，非法 ID 不得回落到创建逻辑。部署 YAML 必须恰好包含一个文档。

统计分页先收敛页码再计算偏移，防止大整数溢出；高消耗排行独立按 token 排序，不受明细排序影响。运行分析的配置选项按 ID 去重，使用最新批次快照名称；profile=0 可筛选无需模型的抽帧批次。前端范围校验前先取消旧统计请求，避免迟到结果覆盖错误。提示词库的增删改刷新不会覆盖尚未保存的固定提示词草稿；非法 JSON 响应明确显示错误。

### 编号目录校验差异诊断

目标冲突诊断只报告实际读取结果，不将列表与路径查询不一致归因于缓存或外部修改。符号链接跳过规则基于应用所在文件系统返回的类型；若网络共享将服务端链接呈现为普通文件，应用无法仅靠该类型识别链接。清理媒体库中的旧链接后重新预览即可，代码没有针对这类链接增加自动跳号或扫描重试；保留目标占用检查、大小写匹配和无覆盖改名保护。

目录预览的 fingerprint 字段保存 v3 JSON 快照（摘要和直接子条目的名称、类型、dev:inode、文件大小与修改时间），沿用原 TEXT 字段，不改变数据库结构。子目录只参与名称、类型、身份校验，不比较子目录大小、修改时间或权限位。文件身份、大小和修改时间继续严格检查。

执行前指纹不一致时，直接比较保存的预览快照和本次失败检查捕获的快照，不再次读取挂载路径代替失败现场。错误显示失败目录，processing_log 列出新增、缺失及字段前后值，最多 20 个差异条目，同时记录总差异数。诊断覆盖未参与编号的文件和子目录，服务日志与编号弹窗均可查看。旧预览只有摘要时明确提示缺少完整快照，更新后需要重新生成预览。身份变化仍然停止，不自动忽略 CIFS inode 差异；诊断不把“读取值不同”等同于“用户修改文件”。
