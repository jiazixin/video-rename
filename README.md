# video-rename

本地视频命名工作台：Go 常驻服务、Vue 前端、SQLite 持久化。登录后按真实目录浏览媒体，手动修改文件或目录名称，使用 FFmpeg 截图与视觉模型自动命名，并随时查看历史和逐次还原。

启动服务不会立即扫描或改名。视频处理由页面中的手动运行或已启用计划触发；成功手动 / 自动命名的视频会跳过后续自动处理，还原后清除该文件的保护标记，可再次自动命名。

## 环境与构建

- Go **1.27.1** 基线；当前支持 macOS / Linux。
- Node.js 22.12+ 与 npm；前端使用 `web/package-lock.json` 锁定依赖。
- 独立抽帧需要 PATH 中的 `ffprobe`、`ffmpeg`；自动命名还需要支持多图输入的 OpenAI 兼容或 Anthropic 视觉模型服务。缺少工具时仍可登录、浏览和手动改名。

从仓库根执行，必须先生成前端再编译嵌入它的 Go 程序：

```bash
npm --prefix web ci
npm --prefix web run build
go build -o bin/video-rename ./cmd/video-rename
cp configs/config.example.yaml configs/config.local.yaml
# 编辑 media-path、auth 等部署配置后启动；模型在登录后的页面设置：
./bin/video-rename --config configs/config.local.yaml
```

默认地址为 `http://127.0.0.1:8790`。如配置 `listen: 0.0.0.0`，使用宿主机 IP 访问。示例密码必须替换，程序拒绝占位密码。

## 配置

```yaml
listen: "127.0.0.1"
port: 8790
media-path: "/srv/videos"
storage: "../data"
tmp-storage: "../.cache"
auth:
  username: "admin"
  password: "请替换为你的密码"
```

- 默认配置为 `configs/config.local.yaml`，也可用 `--config/-f` 指定；保留 `--help`、`--version`。
- 已移除处理参数 `--path/-p`、`--workers`、`--recursive`、`--dry-run`。媒体根目录写 YAML，并发任务数在模型配置中设置，运行范围和递归选项在页面设置。
- 路径相对于配置文件所在目录；`--config` 本身相对于工作目录。配置优先级为 YAML > 内置默认值，不读取环境变量覆盖。
- `media-path` 必填且必须存在；数据库与配置不得放在可操作的媒体根目录内。`storage` 指向数据目录，省略时默认 `../data`，数据库文件名固定为 `data.sqlite`。
- 业务日志、处理标记、历史、计划均在 SQLite 中。旧 `logging` 配置在 Web 服务启动时明确报错；旧 JSONL 文件不删除、不自动导入。
- 配置不会从界面写回。修改部署配置后重启，页面模型配置保存后直接用于新任务；认证变更会使旧会话失效。

模型与提示词设置见 [模型配置](docs/models.md)。完整字段见 [配置参考](docs/configuration.md)，设计与行为见 [整体设计](docs/DESIGN.md) 和 [运行说明](docs/operations.md)。

## 页面与行为

侧边栏按「任务记录」「运行管理」「统计分析」分组：任务记录包含「抽帧记录」「运行记录」，运行管理包含「计划管理」「批次记录」，统计分析包含「模型用量」「运行分析」。「文件目录」和「系统设置」为独立入口。顶部仅显示当前页面名称。各页面支持直接访问、刷新与浏览器前进/后退：`#extractions`、`#history`、`#plans`、`#runs`、`#usage/tokens`、`#usage/analysis`。

1. **文件目录**：按层进入，50 / 100 / 200 条分页，可搜索当前层和筛选目录、视频、图片、音频、其他文件；默认显示全部类型；视频和图片筛选也保留文件夹。目录首次访问时后台建索引，后续按需刷新。右上角可开启多选，支持跨页选择、全选本页、反选本页、批量自动命名和批量还原；切换目录清空选择。当前目录记录在地址栏，刷新、前进和后退均能恢复目录位置。同一目录浏览会话内，返回已访问的目录会恢复分页、筛选和排序，优先用最近访问的列表立即把此前进入的文件夹定位到可视区域中间，再后台更新；定位高亮持续保留，点击空白处或进入目录后取消；目标不存在时恢复原滚动位置。
   “目录内容”列显示该目录最近一次完整索引中的直接子目录、视频和图片数量；未索引时显示“待统计”，进入目录或刷新后更新。
   “抽帧当前目录”和“命名当前目录”并排位于刷新左侧；抽帧覆盖当前目录内全部分页的视频，不受列表搜索或类型筛选影响，弹窗默认包含子目录，可取消递归。多选工具栏依次为“全选、反选、清空、抽帧、命名、标记已处理、取消标记、还原”，支持跨页选择后抽帧。抽帧、命名、标记、取消标记分别使用蓝、紫、绿、琥珀色；标记使用圆圈勾号，取消标记使用圆圈减号，目录与行内入口保持一致。
2. **重命名和还原**：每行手动命名；手动和自动命名的文件扩展名统一小写，还原保留原始大小写；自动命名不限制标题字符数，完整文件名（含扩展名与重名后缀）最多 240 字节，超出时按完整 Unicode 字符截断；目录的自动命名表示处理其中的视频，不为文件夹本身调用模型。还原撤销最近一次有效改名，不能覆盖同名目标。批量自动命名每 100 个目标建立一个运行；批量还原逐项提交，失败项保留供重试。点击视频图标或行内“播放”可在弹窗播放，关闭即停止。音频文件点击淡黄色音频图标即可在弹窗播放，进度、音量、左右方向键快退 / 快进与上一首 / 下一首切换（跨分页，按当前排序和搜索结果）均和视频一致，同样使用浏览器原生解码，不支持时会提示播放失败。图片图标及“查看”按钮打开图片预览，左右按钮及四个方向键在当前目录图片间循环切换（跨分页，跳过视频）（JPEG、PNG、GIF、WebP、AVIF、BMP，取决于浏览器解码支持）。视频使用加大播放窗口，自定义播放控制栏和进度条常驻显示，支持拖动进度、音量及全屏。左右方向键快退 / 快进 10 秒，两侧上一集 / 下一集按钮按当前目录排序和搜索结果跨页切换视频，到首尾提示且不循环。播放使用浏览器原生解码，不做实时转码，不支持的编码会提示播放失败。
   支持单个视频、跨页多选、目录递归“标记已处理 / 取消已处理标记”。标记不改名、不调用模型、不生成还原记录；已有真实命名历史保留。目录操作仅覆盖现有视频（含子目录），新文件仍可自动命名；活动任务中的文件会报告失败，可结束后重试。标记仅存 SQLite，数据库丢失后可重新批量标记。
   自动命名、手动改名、还原和标记后原位更新当前列表，保留筛选、分页与滚动；自动命名也保留勾选。刷新或重新进入时按最新名称排序。目录显示“待处理 / 部分已处理 / 全部已处理”及处理数量，包含子目录和手动标记；未完整索引时显示“待统计”，无视频时显示“暂无视频”。统计以最近扫描结果为准。
   图片和音频视图都提供“一键编号”：仅处理当前目录符合搜索条件的同类文件（含全部分页），保留唯一正整数编号，重复编号按当前排序保留第一张，其余与杂乱名称从最大编号之后续排，不补空号。不同扩展名共用序号，扩展名小写；隐藏的编号文件也保留其号码。位数、前缀、扩展名大小写与紧凑重排等规则在系统设置 → 编号规则中配置，默认不补零、前缀为空、扩展名转小写。预览确认后执行，其他类型和目录不变。“编号记录”按类型分开显示，支持刷新后整批还原；遇到冲突或文件变化会停止，中断时尝试恢复原名。
3. **运行记录**：查看逐个文件的命名、还原等操作结果，成功、失败用独立按钮切换；时间按日期和时刻分两行显示，目录、旧文件名独立分列，自动命名记录显示批次指定的模型，手动操作显示“—”；成功记录显示新文件名，失败记录对应列显示运行批次，长文件名省略显示、悬停查看全文，操作类型分色。显示筛选后总项数和当前页项数，支持 50 / 100 / 200 项分页。失败记录可多选批量重试自动命名，按原模型配置的最新设置提交，每批最多 100 个文件；实际命名成功后自动移除该文件的旧自动命名失败记录，仍失败或未完成则保留。支持日期、操作、名称及运行批次筛选和详情；批次使用自绘下拉框，列出历史中已有批次。成功和失败记录均可展开并复制原始请求 / 响应（密钥脱敏、图片负载省略、每项最多 128 KiB）；失败历史详情还可展开并复制抽帧 / 媒体诊断，包含失败时间点、首次与补试报错、FFmpeg stderr 和预算信息；旧记录无法补录。
4. **系统设置 → Prompt配置**：管理固定提示词与提示词库。固定提示词自动附加在所选提示词末尾，默认要求标题不少于 25 个中文字符、建议 30–50 个中文字符，仅输出一个完整的单行中文标题。修改后仅影响新批次，恢复默认后需保存；已有自定义文本保留。提示词库可新增、编辑、删除，由模型配置下拉选择；被引用时需先更换选择才能删除。
5. **系统设置 → 模型配置**：统一保存名称、服务类型、URL、密钥、模型、温度、输出上限、并发任务数、超时，并从 Prompt配置 的提示词库中下拉选择提示词（必选）。提供智谱、DeepSeek、OpenAI、Claude、Ollama 和自定义预设；可检测模型列表或手动填 ID。圆点设置全局默认，运行与计划选择整套配置。
6. **系统设置 → 抽帧设置**：管理抽帧策略、最大帧数、首尾跳过比例、时长/大小档位及图片尺寸和 JPEG 质量。保存后用于新建任务，已有任务保留原参数。
7. **计划管理与批次记录**：两个独立侧栏入口。「计划管理」配置自动运行时间与范围，支持小时、日、周、五段 Cron 与显式时区，保存后持久化，可编辑、暂停、立即运行和删除。目录选择支持全选本页、反选本页和取消本页选择，并保留其他页的勾选。「批次记录」默认展示全部来源，可筛选手动运行 / 计划触发及命名 / 抽帧任务。已结束批次可整批还原本批次成功改名的文件，冲突或后续变化逐项报告，失败项可重试；活动批次需先取消并等待结束。批次详情显示实际开始时间、结束时间及总耗时（实际开始至结束，不含排队等待）；列表显示耗时和实际开始时刻。运行中的批次在已耗时旁按近期处理速度估算剩余时间（“已运行 X · 剩余约 Y”单行显示，样本不足时显示“预计时间计算中…”）；扫描、取消中及已结束批次不显示估算。

   批次记录右上角提供“新建命名任务”和“新建抽帧任务”。独立抽帧无需选择模型或提示词，不改名、不修改已处理标记，包括已处理视频也会抽帧；截图缓存可供之后的重命名复用。批次标明“重命名 / 抽帧”，抽帧批次支持取消和详情。列表按筛选结果分页，显示总批次数、当前页 / 总页数及当前页条数，支持上一页、下一页和每页 50 / 100 / 200 条；来源切换分别保留页码，任务类型改变回到第一页，刷新与自动更新保留当前页。

   **抽帧记录**为独立侧栏入口，沿用运行记录的“成功记录 / 失败记录”按钮样式，一次显示一个分类，切换保留各自分页；统一收录手动抽帧与重命名中的自动抽帧。每条显示开始时间、结束时间、总耗时、批次（没有时为“—”）、来源、文件和结果；缓存命中显示“复用缓存”。失败可展开详细媒体诊断并复制，支持名称 / 失败原因、日期与批次筛选。抽帧结果在截图准备结束时记录，之后模型命名失败不影响抽帧成功状态。清除抽帧记录删除全部已结束的成功与失败日志，确认框明确范围，保留正在抽帧的记录和截图缓存；升级前未记录的抽帧无法补录。

   批次记录显示批次指定的模型；耗时使用 `d/h/m/s` 紧凑格式，进行中的批次使用动态状态标记。

   批次记录的 Token 按批次累计已记录的模型请求，优先采用模型返回的总 usage；缺失时使用已有的文字 Token 粗估。显示使用十进制 K / M（1K = 1000），悬停可见原数和估算条数。没有可用记录时显示“—”。文字粗估不含图片 Token；该功能启用前的批次不补算。

每个视频独立发送一次多图请求，仅包含该视频的截图与所选提示词，不拼接其他视频的消息或回答。任务创建时保存模型配置和提示词快照（所选提示词正文 + 当时的固定提示词，发送时按此组合）；并发任务数跟随该模型配置的最新值，其他参数编辑只影响新任务。编辑提示词库中的正文会应用于引用它的配置之后创建的运行，进行中批次仍用快照。YAML 完全不支持 sampling、images、server 或提示词字段，不兼容、不自动导入旧模型配置。首次启动可以直接登录，默认记录需要在页面补齐 URL 与模型后才能自动命名。

多个批次可同时扫描、冻结候选和做稳定性观察（默认 30 秒，可在系统设置调整，0 表示禁用等待）。抽帧与模型调用独立调度，模型等待期间继续准备后续视频；同一模型配置的请求共享并发上限。重复计划触发和重叠文件会去重；关机错过的计划不会在开机时集中补跑。外部正在写入视频时，稳定性检查能降低冲突风险，但不等于文件系统事务锁。

8. **统计分析**：侧栏分组包含「模型用量」与「运行分析」两个独立入口（`#usage/tokens`、`#usage/analysis`，`#usage` 默认模型用量）。时间范围均支持最近 1 / 3 / 6 / 12 / 24 小时、今天、最近 7 / 30 天、全部和自定义起止日期时刻，图表与明细共用同一筛选。
   「模型用量」按时间区间统计 token 消耗，可再按模型、模型配置、运行来源和批次筛选。页面包含累计 token、已记录请求、涉及批次、平均每请求等总览，按区间自动分桶（15 分钟 / 小时 / 天 / 月）的消耗趋势（方向键或悬停查看精确值，附完整数据表），模型用量对比与占比，高消耗批次排行和分页批次明细；明细区分区间内消耗与批次累计消耗。统计口径与运行记录一致：优先模型返回的 usage，缺失时使用文字粗估；粗估不含图片 token，未记录的内部重试与模型测试不计入。升级到该版本前的历史批次只保存了批次累计值，会作为“历史汇总”按批次时间（实际开始，缺失用提交时间）归属展示，不伪造成精确的请求时间。
   「运行分析」按时间区间、模型配置和运行来源统计批次处理性能：批次成功率（已完成 / 终态批次）、项目成功率（成功 / 成功+失败）、平均批次耗时（实际开始至结束）、平均处理耗时、吞吐、失败率、跳过率、逐项耗时 P50 / P95 与取消批次数；下方依次为批次耗时趋势、处理结果趋势（成功 / 跳过 / 失败，配色通过 CVD 校验）、吞吐趋势与耗时分布并排、模型配置性能比较、批次大小与耗时散点（悬停或方向键查看批次）、失败分析（条目失败原因归组与批次级失败原因）和分页批次明细（按时间 / 耗时 / 规模排序）。批次按实际开始时间归属区间；逐项耗时自本版本起在 run_items 记录，升级前的批次按批次完成时间近似归属结果趋势，无逐项耗时（页面注明），批次级指标不受影响。

## 持久数据与部署

- 数据库放宿主机本地磁盘，不能放 SMB / NFS 等网络文件系统；SQLite 使用 WAL。
- 运行账号需要媒体目录改名权限、配置读取权限及数据库目录写权限。配置文件建议仅运行账号可读。
- 一个数据库只允许运行一个应用实例；实例锁防止双重调度。根目录身份变化或挂载丢失会阻止继续操作。
- `storage` 目录需要持久化挂载。模型密钥及任务模型快照加密保存在 SQLite，加密主密钥位于数据库旁的 `<storage>/data.sqlite.key`；备份与恢复必须同时保留该文件。不要删除数据库来“清空日志”，否则会同时丢失防重复标记和还原历史。
- 冷备份：停止服务，完整备份数据库所在状态目录，再启动。在线备份应使用 SQLite Backup API，不单独复制正在写入的主数据库文件。
- 恢复旧备份后先暂停计划并人工核对备份之后的文件改动。文件系统与旧数据库不自动回滚到同一时间点。
- 如经反向代理对外提供访问，应由代理启用 HTTPS；应用不信任客户端伪造的转发头。

## 通知设置

“系统设置 → 通知设置”支持企业微信、Telegram、钉钉、Bark 与通用 Webhook，每个渠道可独立启用或仅在失败时通知。保存后可主动发送测试通知；敏感字段留空保持原值，钉钉加签密钥可显式清除。关闭后停止待发送通知，重新开启只通知之后新建的批次，不补发旧记录。

通知在批次结束后发送：批次编号、状态、来源、目录/文件目标、模型、总数、成功/跳过/失败/未完成数量、提交/实际开始/完成时间（最近登录浏览器的时区，含 UTC 偏移）和耗时。目标名称最多显示 5 项。通知不会携带视频、截图、提示词或模型密钥。

企业微信填群机器人完整 Webhook；Telegram 填 Bot Token 与 Chat ID；钉钉填机器人 Webhook 和可选加签密钥（关键词校验可设置 `video-rename`）；Bark 填以设备 Key 结尾的推送地址（可带末尾斜杠，不含示例标题/正文），支持自建服务；程序转换为标准 `/push` JSON 请求；通用 Webhook 接收 `event: batch.finished`、`title`、`body` 的 JSON POST。服务端需要能够访问对应渠道。

通知配置加密存入 SQLite，备份仍需同时保留数据库与 `.key`。发送队列持久保存、每次超时 10 秒、失败最多尝试 3 次，结果在页面查看，不影响命名任务。远端已收到但响应丢失或进程在发送后中断时，重试可能重复送达；可用批次编号识别重复通知。

## 系统设置与临时截图

侧栏「系统设置」使用页签组织「处理与缓存」「编号规则」「Prompt配置」「模型配置」「抽帧设置」「通知设置」。「编号规则」分别设置图片与音频一键编号的规则：编号最小位数（如 3 位时写成 001）、编号前缀（仅“前缀 + 数字”的文件视为已编号）、扩展名转小写（默认开启）、紧凑重排（默认关闭，开启后忽略空号从 1 连续编号）及图片与音频在同一目录共用一套序号（默认关闭）。默认值与历史行为一致；规则保存后用于之后的预览，已生成的批次与整批还原不受影响。处理与缓存中可设置并发抽帧数（默认 8 个视频）、临时目录大小（默认 10 GB，十进制）和文件稳定性等待时长（默认 30 秒，0–3600 秒，0 禁用等待）。抽完一个视频即可发送给模型，不必等整组抽完。抽帧可持续推进整个批次，不再受 64 个视频上限限制；受抽帧并发与临时目录容量约束，容量不足时等待，释放空间后继续。等待模型的截图受保护，不会为继续抽帧而被清理。

`tmp-storage` 指定可复用截图缓存的位置，默认 `../.cache`，相对于配置文件目录；不能位于媒体根目录内。程序只维护其下的 `video-rename-frames-v1/`，运行账号须有读写权限，缓存无需备份。修改位置需要重启，迁移位置后旧目录不再自动维护。

独立抽帧完成后保留截图；改名成功后删除对应截图；失败或取消保留完整截图供重跑复用。连续 3 天未使用自动清理；容量不足时优先清理闲置旧缓存（包括独立抽帧已完成的截图），使用中的截图受保护，空间不足暂停新抽帧。中断的半成品不复用。文件身份、大小、修改时间或抽帧设置改变时重新抽帧，改模型或提示词可以继续使用截图。页面可查看缓存位置、已用容量、视频数及抽帧预留空间。
